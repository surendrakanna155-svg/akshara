====================================================
1. PURPOSE
====================================================

Define production-ready database standards,
DDL strategy and SQL implementation guidelines.

====================================================
2. DATABASE PLATFORM
====================================================

Engine:
PostgreSQL

Provider:
Supabase

====================================================
3. PRIMARY KEY STANDARD
====================================================

All tables use:

UUID PRIMARY KEY

Example:

id UUID PRIMARY KEY

====================================================
4. AUDIT COLUMN STANDARD
====================================================

Every business table must contain:

created_at TIMESTAMP
created_by UUID

updated_at TIMESTAMP
updated_by UUID

====================================================
5. SOFT DELETE STANDARD
====================================================

Columns:

is_deleted BOOLEAN DEFAULT FALSE

deleted_at TIMESTAMP

====================================================
6. MULTI TENANT STANDARD
====================================================

Every school table contains:

school_id UUID

Required for:

RLS Policies

====================================================
7. INDEXING STANDARD
====================================================

Mandatory Indexes:

school_id
branch_id
academic_year_id

Frequently searched columns

====================================================
8. STUDENTS TABLE DDL TEMPLATE
====================================================

students

id UUID
school_id UUID
branch_id UUID

admission_number VARCHAR(100)

first_name VARCHAR(100)
last_name VARCHAR(100)

date_of_birth DATE

created_at TIMESTAMP

====================================================
9. USERS TABLE DDL TEMPLATE
====================================================

users

id UUID

email VARCHAR(255)
mobile VARCHAR(20)

status VARCHAR(50)

====================================================
10. ATTENDANCE TABLE STANDARD
====================================================

Attendance records immutable.

Corrections stored separately.

====================================================
11. FINANCE TABLE STANDARD
====================================================

No financial deletion.

Only:

Reversal Entries

12. FILE STORAGE STANDARD
====================================================

file_url
