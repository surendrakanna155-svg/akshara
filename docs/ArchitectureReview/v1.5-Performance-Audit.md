# Architecture Audit — v1.5 Performance

**Date:** June 2026  
**Scope:** Riverpod providers, widget rebuilds, screen composition, routing

---

## Provider Architecture Review

### Large provider files

| File | Provider declarations (approx) | Pattern |
|------|-------------------------------|---------|
| `hr_providers.dart` | 46 | loading/error/empty/filter per screen |
| `transport_providers.dart` | 45 | Same |
| `control_center_providers.dart` | 45 | Same |
| `inventory_providers.dart` | 45 | Same |
| `alumni_providers.dart` | 45 | Same |
| `library_providers.dart` | 44 | Same |
| `hostel_providers.dart` | 41 | Same |
| `management_providers.dart` | 40 | Same |

**Observation:** Each ERP screen adds 4–5 `StateProvider` flags + 1–2 data providers. **~45 providers × 11 modules ≈ 495 ERP state providers** — all in-memory, O(1) reads from mock repositories.

### Provider read patterns

| Pattern | Assessment |
|---------|------------|
| `ref.watch(repositoryProvider).get*()` | ✅ Sync read; no async overhead |
| Loading triads | ✅ Short-circuit to `null` — avoids data fetch |
| Filter providers | ✅ Derived providers recompute on filter change only |
| Integration overrides | ⚠️ `StateProvider<Map>` — full map watch triggers broad rebuilds |
| `adminNavDestinationsProvider` | ✅ Lightweight filter list |

## Widget Rebuild Patterns

| Pattern | Prevalence | Risk |
|---------|------------|------|
| `ConsumerWidget` screens | High (all ERP) | Full screen rebuild on any watched provider change |
| Multiple `ref.watch` in build | Common | Cascading rebuilds when loading/error toggled |
| `pumpAndSettle` in tests | Most screen tests | Indicates async animation; acceptable |
| `FinanceResponsiveGrid` | All ERP KPI rows | `LayoutBuilder` — rebuilds on constraint change (expected) |
| `DataTable` in `SingleChildScrollView` | 65+ tables | No virtualization — **O(n) rows rendered** |
| Chart widgets | ~30 dashboards | Custom paint — moderate cost |

### Unnecessary rebuild candidates

1. **Filter bar + body in same ConsumerWidget** — filter change rebuilds entire table section (acceptable for mock data sizes).
2. **AdminShell + module body** — shell rebuilds when nav provider changes (rare).
3. **No `select` / `Provider.select`** — not used anywhere; opportunity for micro-optimization.

## Mock Dataset Loading

| Aspect | Impact |
|--------|--------|
| Mock repos return static const data | **Zero I/O** — instant |
| No lazy loading | All data loaded per provider read |
| No pagination | Tables render full mock lists (4–8 rows typical) |
| Future API | Network latency + JSON parse per screen — **bottleneck at API layer** |

## Routing Performance

| Aspect | Assessment |
|--------|------------|
| `NoTransitionPage` for ERP | ✅ No animation overhead between tabs |
| Single `GoRouter` instance | ✅ |
| `debugLogDiagnostics: true` | ⚠️ Log overhead in debug |
| Route count ~100 | ✅ GoRouter handles efficiently |
| No deferred loading / code splitting | ⚠️ Web bundle includes all modules |

---

## Future API Bottlenecks

| Area | Risk |
|------|------|
| Sync `getDashboard()` → HTTP | Will block UI isolate unless refactored to `FutureProvider` |
| No caching layer | Every navigation re-fetches |
| No pagination on tables | Large student/fee lists will degrade |
| 65+ DataTables without virtualization | 500+ row API responses will jank |
| No request deduplication | Multiple providers calling same endpoint |

---

## Findings Summary

| Priority | Finding |
|----------|---------|
| P1 | Migrate to `AsyncNotifier` / `FutureProvider` before API |
| P1 | Add pagination to registry, collections, employee lists |
| P1 | Virtualize large tables (`PaginatedDataTable` or custom) |
| P2 | Use `ref.watch(provider.select(...))` for KPI-only rebuilds |
| P2 | Flutter web deferred imports per ERP module |
| P2 | Gate `debugLogDiagnostics` behind `kDebugMode` |
