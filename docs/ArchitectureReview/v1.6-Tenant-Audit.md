# v1.6 Tenant Architecture Audit

## Models

### `TenantContext`
- `tenantId` (required)
- `schoolId` (optional)
- `organizationId` (optional)
- `userId` (required)

### `RepositoryQuery`
Passed to every repository method:
```dart
Future<T> getData({required RepositoryQuery query});
```

### `CurrentUserContext`
Combines `TenantContext` + display name + phone for downstream services.

## Provider Chain

```
AuthClaims.tenantId → tenantContextProvider → repositoryQueryProvider → Repository
```

Demo defaults (`tenant_demo_001`, `school_akshara_001`, `org_akshara_001`) used when claims absent.

## Provider Pattern

```dart
final xFutureProvider = FutureProvider<T>((ref) async {
  return repo.getX(query: ref.watch(repositoryQueryProvider));
});
final xProvider = Provider<T?>((ref) => watchRepositoryFuture(...));
```

## Session Persistence

`AuthClaims` persisted in `auth_session_v2`:
- `userId`, `role` (ErpRole), `tenantId`, `schoolId`, `organizationId`, `permissions[]`

## Remaining Production Items

- Multi-tenant switching UI (SuperAdmin)
- Tenant isolation validation in API layer
- Cross-tenant access denial at repository boundary
- Tenant-scoped cache keys in offline storage
