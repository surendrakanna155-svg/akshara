# Architecture Review — v18.1 Autonomous QA Platform

**Tag:** `v18.1-autonomous-qa-platform`  
**Date:** June 2026  
**Score:** 86 / 100 (QA infrastructure readiness)

---

## Summary

Introduced a permanent `qa/` workspace with Maestro journeys, shared subflows, route inventory generation, and a one-command regression runner. Flutter widget/golden tests remain the primary route-coverage layer; Maestro adds device-level journey validation with screenshots and JUnit reports.

---

## Architecture

```
qa/run_all_qa.sh
  ├── extract_route_inventory.py → qa/inventory/routes.json
  ├── flutter analyze + flutter test
  ├── maestro test qa/journeys/*.yaml
  │     └── qa/maestro/flows/_shared/*.yaml
  └── generate_report.sh → coverage_summary.json + findings.json
```

---

## Design decisions

| Decision | Rationale |
|----------|-----------|
| QA APK with `ENABLE_DEMO_AUTH=true` | Deterministic OTP for automation |
| Shared subflows in `maestro/flows/_shared/` | DRY login/ERP navigation |
| Reports under `qa/reports/<run_id>/` | Evidence per run, no overwrite |
| No auto-fix in Maestro loop | Findings only — business logic unchanged |
| Flutter router smoke retained | 123 routes without device dependency |

## Coverage gaps

| Gap | Severity | Mitigation |
|-----|----------|------------|
| Maestro ERP drawer uses coordinate tap | Medium | Add semantics keys in future (optional) |
| Dynamic routes (`:id`) not Maestro-tested | Medium | Flutter smoke + integration tests |
| iOS Maestro journeys not yet added | Low | Extend with iOS simulator config |
| Teacher staging API login | High | Backend seed (QA-003) |

---

## Recommendations

1. Run `SMOKE_ONLY=1` on every PR via CI when emulator available.
2. Nightly full `./qa/run_all_qa.sh` with artifact upload of `qa/reports/`.
3. Extend `findings.json` with Maestro `--analyze` when stable.
