## Mock store

`MockFinanceRepository` uses `_FinanceMutableStore` for:

- Fee structures (create/update)
- Student accounts (create/update/assign)
- Refund requests (create/approve)
- Scholarships (create/update)
- Settings (section item updates)

Read methods for dashboard, collections, defaulters, and reports remain static seed data.

## Findings

### Strengths

- Full 10-method write parity with read-layer conventions
- Mutable mock store enables offline workflow testing
- Minimal screen diffs — callback wiring only

### Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Audit uses `financeHandoffSent` for all finance actions | Low | Metadata distinguishes `action`; dedicated enum values deferred |
| Assign fee plan still updates admissions handoff locally | Low | Admissions handoff status API out of scope; local override retained |
| No OpenAPI contract validation | Medium | Staging validation planned |

## Verdict

**Finance write API client: READY** — 10/10 methods implemented with repository parity, provider wiring, and test coverage. Backend deployment is the remaining blocker.
