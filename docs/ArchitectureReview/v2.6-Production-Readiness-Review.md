## 7. RBAC Analysis

### 7.1 `permissions.dart`

- 22 fine-grained permissions: `view*` + `manage*` per module, plus `approveAdmissions`, `approveRefunds`, `viewAdminHub`
- Immutable `PermissionSet` with `contains` / `containsAny` / `containsAll`

### 7.2 `rbac_service.dart`

- Single `RbacService` + `userPermissionsProvider`
- Resolution order: server permission cache (12h TTL) → JWT claims → role matrix fallback
- Convenience providers: `canView*`, `canManage*` for Admissions, Finance, SIS

### 7.3 `route_guards.dart`

| Guard | Purpose |
|-------|---------|
| `AuthenticatedGuard` | Session required |
| `RoleGuard` | ERP role set |
| `PermissionGuard` | Single permission |
| `ErpRouteGuard` | Location → `view*` permission + **accessDenied audit** |
| `ControlCenterGuard` | SuperAdmin + viewControlCenter (unused in router) |

**Route coverage:** All 12 ERP prefixes mapped in `kErpRouteViewPermissions`. Verified by `route_protection_inventory_test.dart`.

**Gaps:**
- `manage*` permissions **not** enforced at route level (only view)
- Mutation providers enforce manage/approve for Admissions (and partial Finance/SIS audit helpers)
- Mobile routes use `UserRole` only — no ERP permission matrix

## 8. Tenant Architecture

### 8.1 `tenant_provider.dart`

- `tenantContextProvider` derives from JWT claims; falls back to `TenantContext.demo`
- `repositoryQueryProvider` propagates tenant/school/org/user to all repository calls

### 8.2 `tenant_interceptor.dart`

- Injects `X-Tenant-Id`, `X-School-Id`, `X-Organization-Id`, `X-User-Id` headers
- Optional `requireTenant` rejection for missing tenant
- Wired via `dioProvider` → `createDioClient(tenantAccessor: () => ref.read(tenantContextProvider))`

**Gaps:** Mock data is not tenant-scoped; anonymous API mode allowed; cross-module integration providers may bypass query in edge cases.

## 14. Security Concerns

1. **Client-only authorization** — bypass via direct API calls or tampered JWT claims
2. **No row-level tenant isolation on server** (client assumption only)
3. **Plaintext token storage** in SharedPreferences
4. **Demo tenant fallback** when authenticated without claims
5. **Unknown JWT role → superAdmin** (per v2.1 finding; verify still present in role mapping)
6. **Audit trail is local and trimmable** — not tamper-evident
7. **Document upload metadata-only** — no multipart validation (Admissions)
8. **verifyOtp swallows errors** — returns null on any failure (auth UX / security logging gap)
