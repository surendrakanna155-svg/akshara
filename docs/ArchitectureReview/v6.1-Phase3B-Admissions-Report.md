## Slice 1 — Leads

### Delivered

- **Migration:** `20260611100000_admissions_slice1_leads.sql`
- **Table:** `admissions_leads` with school-scope RLS
- **Routes:**
  - `GET /admissions/leads` — list (paginated)
  - `POST /admissions/leads` — create (`manageAdmissions`)
  - `GET /admissions/leads/:id` — detail
  - `PUT /admissions/leads/:id` — update (`manageAdmissions`)
- **Seed:** Probe leads School A / School B

### Technical report

Handlers delegate to `admissions_repository.ts` inside `withTenantContext`. List responses use envelope `{ data: { items, pagination } }` matching Flutter `ApiEnvelopeDto`. API responses use camelCase; request bodies use snake_case per client DTOs.

### Security verification

- Org-scope JWT → middleware 403 before DB (operational scope)
- School A cannot read School B lead via RLS (`school_a_cannot_see_school_b_leads`)
- Org cannot read raw leads (`org_scope_denied_raw_admissions_leads`)

### Contract-test status

- Flutter DTO serialization: **10/10 pass** (`admissions_write_contract_test.dart`)
- Deno mapper + permission tests: **pass**
- Live API contract against staging: **pending deploy** (see Staging)

## Slice 3 — Documents

### Delivered

- **Migration:** `20260611300000_admissions_slice3_documents.sql`
- **Table:** `admissions_documents`
- **Routes:**
  - `GET /admissions/documents` — list (supporting review UI)
  - `POST /admissions/documents/upload` — upload metadata (`manageAdmissions`)
  - `POST /admissions/documents/:id/approve` — verify (`approveAdmissions`)
  - `POST /admissions/documents/:id/reject` — reject (`approveAdmissions`)

Upload auto-links `application_id` when a lead has an application.

### Security verification

Approve/reject gated on `approveAdmissions`. Document rows scoped to school via RLS.

## Slice 4 — Approval, Enrollment, Student / Parent

### Delivered

- **Migration:** `20260611400000_admissions_slice4_approval_enrollment.sql`
- **Tables:** `admissions_approvals`, `admissions_enrollments`
- **Student policies:** `students_school_insert`, `student_guardians_school_insert`
- **Function:** `app.lookup_guardian_user_for_enrollment(phone)` for parent linking
- **Routes:**
  - `POST /admissions/approval/:id/approve` — `approveAdmissions`
  - `POST /admissions/approval/:id/reject` — `approveAdmissions`
  - `POST /admissions/enrollments` — creates `students` row, links guardian when phone matches, records enrollment

### Security verification

Enrollment uses `withTenantContext` only. Parent link via controlled SECURITY DEFINER lookup (phone → user id); no `service_role`. Student `organization_id` / `school_id` set from JWT context in INSERT.
