## Executive Summary

Akshara ERP v18.8 is **strongly ready for a scoped mock-mode pilot** and **conditionally ready for a live-api pilot school** if deployment stays within the frozen module set. It is **not yet ready for unrestricted production SaaS**.

| Dimension | Score | Notes |
|-----------|------:|-------|
| **Client QA readiness (mock / demo pilot)** | **94 / 100** | Aligns with Cycle 4 gates |
| **Live pilot readiness (API + staging)** | **81 / 100** | Blocked on live API sign-off + ops verify |
| **Full production SaaS readiness** | **72 / 100** | TLS, pen test, monitoring, build pipelines open |

**Pilot verdict:** **Yes — with explicit scope freeze.** Deploy for a single pilot school using Admissions → SIS → Finance (assign + collect) and Teacher attendance as primary write paths. Defer HR payroll writes, inventory procurement, transport route creation, and ERP exam administration until product assigns those milestones.

## Blocker Classification Key

| Type | Meaning |
|------|---------|
| **A** | Missing QA coverage — feature exists or partially exists; needs keys, Patrol, integration, or RBAC device tests |
| **B** | Missing UI implementation — repository or contract ready; screen/dialog/workflow action absent |
| **C** | Missing provider / business logic — mutation layer, mock sync, or cross-module propagation not wired |
| **D** | Product scope not yet implemented — module, route, or journey not in roadmap / intentionally deferred |

**Effort:** S = 1–2 days · M = 3–5 days · L = 6–10 days · XL = 11+ days  
**Readiness gain:** Estimated lift to overall client QA readiness (mock pilot weighting).

## Can Akshara ERP Be Considered Production-Ready for Pilot-School Deployment?

### Mock-mode pilot (QA APK, `ENABLE_API_MODE=false`)

**Yes — recommended.**

Evidence:

- Core revenue and enrollment chain is Patrol-proven end-to-end.
- 1302 unit/widget/contract tests + 22 Patrol suites green.
- RBAC route guards and mutation deny tests exist for admissions and finance.
- Feature freeze is active per Roadmap; scope control is feasible.

**Conditions:**

1. Publish a **pilot scope document** (see [Recommended freeze scope](#recommended-freeze-scope)).
2. Train school staff on **mock limitations** (HR/inventory/transport writes are read-only or demo data).
3. Do not claim exam administration or ERP academic attendance reporting as supported.

### Live-api pilot (single school, staging/production API)

**Conditional yes — not yet a default go.**

Required before go-live:

| # | Requirement |
|---|-------------|
| 1 | `./scripts/pilot_staging_verify.sh` — 13/13 PASS on target environment |
| 2 | Live write APIs for Admissions, Finance, SIS validated (not mock) |
| 3 | OTP auth + permission sync on real tenant |
| 4 | Pilot issue tracker process active ([`Pilot-Issue-Tracker.md`](../Operations/Pilot-Issue-Tracker.md)) |
| 5 | Frozen module list communicated to school (no HR payroll, transport route create, inventory PO) |
| 6 | Rollback + backup runbook exercised once |

Without items 1–3, live pilot risk is **High** (data integrity and auth unknowns outweigh client test confidence).

### Full production SaaS (multi-tenant, SLA)

**No — not at v18.8.**

Open: TLS, pen test, monitoring alerts, tamper-evident audit, load test (T8), production build pipelines, multi-region DR.

Target: **98+ readiness** per checklist scoring guide — currently ~72 weighted.

## Recommended Freeze Scope (pilot school)

### In scope — supported write paths

| Module | Allowed operations |
|--------|-------------------|
| **Admissions** | Lead → application → enrollment → approval |
| **SIS** | Admissions conversion → student registry |
| **Finance** | Fee assignment from handoff → invoice → collection → receipt lookup |
| **Teacher (mobile)** | Class attendance mark + submit |
| **Parent (mobile)** | Read fees, attendance, timetable, notices (Pay Now = demo unless live payment integrated) |
| **Student (mobile)** | Read homework, attendance, exams, timetable |

### In scope — read / navigate only

ERP dashboards and sub-nav for **HR, Transport, Library, Hostel, Inventory, Alumni, Management, Control Center** — Patrol-proven navigation; **no write commitments**.

### Out of scope — explicit exclusions

| Area | Reason |
|------|--------|
| ERP exam administration | **D** — product not implemented |
| ERP academic attendance admin | **D** — module absent |
| HR employee create / payroll process | **C** — no mutation providers |
| Inventory PO / stock receive / allocate | **C** — no mutation providers |
| Transport route create / seat assignment | **C** — no mutation providers |
| Finance report PDF export | **B** — UI stub |
| SIS bulk export file delivery | **B/A** — assert label only |
| Intelligence Copilot actions | **D** — read-only assistants |
| Multi-school / control-center provisioning | Ops milestone — not single-school pilot |
