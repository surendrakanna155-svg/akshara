## Architecture Improvements

- **Provider → Repository abstraction** — mock data moved out of feature providers into `Mock*Repository` classes
- **API-ready structure** — screens and providers depend on interfaces, not inline `_mock*()` functions
- **Reduced future migration effort** — swap `MockFinanceRepository` (etc.) for API implementations without touching UI layer
- **Cross-module consistency** — Admissions, Finance, and SIS share the same repository pattern via `repository_providers.dart`

### Repository contracts

| Repository | Key methods |
|------------|-------------|
| `AdmissionsRepository` | Dashboard, leads, applications, documents, enrollments, handoffs, approval queue, reports, settings |
| `FinanceRepository` | Dashboard, collections, fee structures, student accounts, installments, Phase 2 data (defaulters, refunds, discounts, reports, settings) |
| `SisRepository` | Dashboard, students, class/section/year options |

## Integrations

| Module | Integration point |
|--------|-------------------|
| **Admissions AD-08** | Fee handoff queue → Finance assignment (FN-04); handoff status sync via `feeHandoffStatusOverridesProvider` |
| **Student SIS** | Fee account IDs (`acct_*`) linked in collection detail and defaulters; SIS profile reads `financeStudentAccountsProvider` |
| **Parent Fees (PA-03)** | Fee structures and installment plans align with Finance mock data |
| **Parent Receipts (PA-11)** | FN-06 receipt links route to `/parent/receipts/:receiptId` |

### End-to-end flow

```
Admissions (AD-08 Fee Handoff)
    → Finance (FN-04 Assignment → FN-05 Collections → FN-06 Detail)
        → Student SIS (SIS-02 Registry, SIS-03 Profile)
            → Parent App (PA-03 Fees, PA-10 Payment, PA-11 Receipts)
```
