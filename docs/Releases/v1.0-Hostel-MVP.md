# Hostel MVP Release

**Version:** `v1.0-hostel-mvp`  
**Date:** June 2026  
**Codename:** Hostel MVP (HO-01 → HO-08)  
**Prior release:** Transport MVP (v0.8)

## Overview

Hostel MVP delivers eight admin screens for residential operations: dashboard KPIs, SIS-linked student registry, room inventory, session attendance, leave workflow, mess management, visitor tracking, and reports. Data flows through `HostelRepository` → `MockHostelRepository` with Riverpod providers — no inline mock data in screens.

| ID | Screen | Route |
|----|--------|-------|
| HO-01 | Dashboard | `/hostel/dashboard` |
| HO-02 | Students | `/hostel/students` |
| HO-03 | Rooms | `/hostel/rooms` |
| HO-04 | Attendance | `/hostel/attendance` |
| HO-05 | Leave | `/hostel/leave` |
| HO-06 | Mess | `/hostel/mess` |
| HO-07 | Visitors | `/hostel/visitors` |
| HO-08 | Reports | `/hostel/reports` |

Bare `/hostel` redirects to `/hostel/dashboard`.

---

## Features Delivered

### HO-01 — Dashboard

- Six KPI tiles (occupancy, present, missing, visitors, mess cost MTD, fee pending)
- Block occupancy and session attendance summaries
- Health alerts and missing-student warning banner
- AI insight card with SIS student link

### HO-02 — Students

- SIS-linked hostel residents (`SIS-STU-*` IDs)
- Block, room, bed assignment and fee pending column
- Navigation to SIS student detail and Finance fee structures

### HO-03 — Rooms

- Room catalog with block, floor, type, beds, occupancy, facilities
- Derived KPI row (room count, occupied, avg occupancy)
- Status filters (All, Occupied, Vacant, Maintenance)

### HO-04 — Attendance

- Morning/evening/night session roster
- Status filters (Present, Absent, On leave)
- Parent notification column and missing alert banner

### HO-05 — Leave

- Pending, approved, rejected, and active gate passes
- Parent contact and gate pass ID columns
- Parent App leave integration link

### HO-06 — Mess

- Weekly menu table with dietary tags
- Consumption cost trend chart
- Finance expense ledger placeholder (FN-05)

### HO-07 — Visitors

- Active visitors and visitor log tables
- QR pass preview placeholder
- Parent App dashboard integration link

### HO-08 — Reports

- Six-report catalog with download placeholders
- Occupancy trend chart
- Attendance-by-block segment panel
- Mess cost trend (Finance integration placeholder)

## Repository Architecture

### Repository contract

`HostelRepository` (`lib/core/repositories/interfaces/hostel_repository.dart`):

| Method | Returns |
|--------|---------|
| `getDashboard()` | `HostelDashboardData` |
| `getStudents()` | `List<HostelStudent>` |
| `getRooms()` | `List<HostelRoom>` |
| `getAttendanceRecords()` | `List<HostelAttendanceRecord>` |
| `getLeaveRequests()` | `List<HostelLeaveRequest>` |
| `getMessData()` | `HostelMessData` |
| `getVisitors()` | `HostelVisitorsData` |
| `getReports()` | `HostelReportsData` |
| `getOccupancyMetrics()` | `HostelOccupancyMetrics` |

### Repository implementation

`MockHostelRepository` (`lib/core/repositories/mock/mock_hostel_repository.dart`) — integrated mock data aligned with SIS student IDs (Arjun Patel `SIS-STU-10421`, Emma Thomas, Ananya Reddy, Priya Sharma).

### Provider wiring

```
Screen → hostel*Provider → hostelRepositoryProvider → MockHostelRepository
```

Registered in `lib/core/repositories/repository_providers.dart` as `hostelRepositoryProvider` with `useApiRepositoriesProvider` swap to `ApiHostelRepository`.

Feature providers in `lib/features/hostel/hostel_providers.dart` with loading/error/empty `StateProvider` flags per screen.

## Known Limitations

- QR visitor pass and gate pass are placeholder UI only
- No API integration — all data via `MockHostelRepository` (API scaffolding throws `ApiNotConnectedException`)
- Hostel fee billing not implemented (Finance placeholders only)
- Export/download buttons on reports are UI placeholders
- Floor plan grid visualization deferred (table/card fallbacks used)
