# v1.6 — Security & RBAC Foundation

**Release type:** Architecture / Security (no new ERP business features)  
**Status:** Complete  
**Tests:** 503 passing · Analyzer: 0 issues

## Summary

Akshara ERP moves from demo architecture to production-ready security foundations:

- Fine-grained `Permission` enum and `RolePermissionMatrix`
- Central `RbacService` with Riverpod providers
- Route guards with in-place **Access Denied** (`AksharaErrorState`)
- Tenant context propagated to all repositories
- Mock JWT `AuthClaims` persisted in session storage (`auth_session_v2`)
- Async tenant-aware repository interfaces
- Permission-driven admin navigation (hidden, not disabled)

## Control Center Policy

**Super Admin only.** `SchoolAdmin`, `Principal`, `FinanceAdmin`, and all other roles are denied `/control-center/*` at the route guard layer and the item is **hidden** from the navigation rail.

## Staff Demo Sessions

- `AuthNotifier.signInStaff()` — programmatic staff login with claims
- `staffErpRoleProvider` + `setStaffErpRole()` — persisted ERP role preference
- Default staff role: `superAdmin` (backward compatible with v1.5 smoke tests)

## Migration Notes

- Session key bumped: `auth_session_v1` → `auth_session_v2` (claims field added; v1 sessions still readable)
- All repository methods: `Future<T> method({required RepositoryQuery query})`
- Screen tests use `erpWidgetTestOverrides()` for stable async data loading
