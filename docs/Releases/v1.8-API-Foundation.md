# v1.8 — API Foundation & Authentication

**Release type:** Infrastructure (no new ERP business features, screens, or modules)  
**Status:** Complete  
**Tests:** 529 passing · Analyzer: 0 issues  
**Baseline:** v1.7 production readiness 58/100 → v1.8 **68/100**

## Summary

v1.8 delivers production-shaped API infrastructure without wiring business endpoints. The app continues to use mock repositories by default; enabling API mode requires both environment configuration and per-module feature flags.

### Goals delivered

| Goal | Status |
|------|--------|
| Production authentication foundation | ✅ Token storage, refresh hooks, claims expiry |
| Production network layer | ✅ Dio interceptors (auth, tenant, correlation, errors) |
| Production API repository foundation | ✅ Environment-driven base URL, live tenant/token accessors |
| Feature-flagged API rollout | ✅ 11 per-module `*ApiEnabledProvider` flags |
| Graceful API failure handling | ✅ `ApiFailure` + `AksharaErrorState.fromFailure` |
| Contract testing foundation | ✅ Admissions, Finance, SIS mock/API parity tests |

### Explicitly out of scope

- Business HTTP endpoints (still `ApiNotConnectedException`)
- New ERP screens or modules
- Route or navigation changes
- Repository interface changes

## Enabling API mode (development)

```bash
flutter run --dart-define=APP_ENV=staging
```

Then override providers in tests or a dev bootstrap:

```dart
environmentProvider.overrideWithValue(Environment.staging.copyWith(enableApiMode: true));
financeApiEnabledProvider.overrideWithValue(true);
```

Only modules with both flags enabled swap to `Api*Repository`. Unimplemented endpoints still throw `ApiNotConnectedException` until v1.9+ endpoint work.
