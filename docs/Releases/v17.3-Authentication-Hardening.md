# Release v17.3 — Authentication Hardening

**Tag:** `v17.3-authentication-hardening`  
**Date:** June 2026  
**Version:** 17.3.0+173  
**Severity:** Critical pilot blocker fix

---

## Root cause

iPhone release builds use `APP_ENV=staging` with `ENABLE_API_MODE=true`, but:

1. **Staging did not set `disableDemoAuth`** — mock OTP path remained active
2. **`verifyOtp` accepted any 6-digit code** — not just valid server OTP
3. **Mobile login never called `AuthRepository`** — bypassed API entirely; role came from UI picker → wrong dashboard with demo data
4. **`authApiEnabledProvider` was hardcoded `false`** — staff/mobile API auth never wired for release flags

---

## Fixes

| Area | Fix |
|------|-----|
| Environment | Staging defaults `disableDemoAuth: true`; opt-in via `ENABLE_DEMO_AUTH=true` |
| Mobile auth | API login/verify when hardened + `AUTH_API_ENABLED` |
| Mock OTP | Only `123456` in explicit testing mode; random OTP rejected |
| Session restore | Hardened builds require valid tokens + claims |
| Login UI | Production: phone only; Testing: explicit account chips |
| Staff mock | Removed any-6-digit bypass |

## Remaining risks

- OTP in API response is dev-mode only — production needs SMS provider
- Parent linked-child names from API are placeholders until profile API enriches
- Session restore on device may need re-login after upgrade (clears invalid mock sessions)
