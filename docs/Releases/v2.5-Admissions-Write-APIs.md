# v2.5 — Admissions Write APIs & Workflow Completion

## Summary

Completes the Admissions module write layer on top of v1.9 read APIs. All CRM and workflow actions (leads, applications, enrollment, documents, approval, finance handoff) now flow through the repository pattern with RBAC guards, audit logging, and AsyncNotifier mutation providers.

## Architecture

```
Screen → AsyncNotifier mutation provider → AdmissionsRepository → ApiAdmissionsRepository → AdmissionsRemoteDataSource → Dio
```

- Feature flag: `admissionsApiEnabledProvider`
- RBAC: `canManageAdmissionsProvider`, `canApproveAdmissionsProvider`
- Audit: 12 admissions-specific `AuditEventType` values with `entityId`, `tenantId`, `userId`, timestamp
- Errors: `ApiFailure` / `ApiFailureMapper` — no raw Dio exceptions reach UI
