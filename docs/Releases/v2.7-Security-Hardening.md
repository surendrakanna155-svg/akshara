# v2.7 — Security Hardening

Release date: 2026-06-07

## Summary

Production security hardening for auth, RBAC, and audit — no new ERP modules, screens, or routes.

## Authentication Security

| Feature | Implementation |
|---------|----------------|
| Secure token storage | `TokenStorage` → `SecureStorageBackend` (`FlutterSecureStorage` native, `PreferencesStorageBackend` web/tests) |
| JWT claim validation | `JwtValidator` — sub, tenant_id, exp, iat + 60s clock skew |
| Refresh token rotation | `RefreshTokenRotationTracker` — reuse detection |
| Session expiration | `SessionExpirationPolicy` — max age + idle timeout |
| Token revocation | `TokenRevocationService` — local + server hooks |
| Device session metadata | `DeviceSessionMetadata` + `SessionMetadataStorage` |
| Logout all sessions | `AuthNotifier.logoutAll()` → `POST /auth/sessions/logout-all` |
| Auth interceptor hardening | Revocation check, JWT validation before attach |

## Server RBAC

| Feature | Implementation |
|---------|----------------|
| Permission cache | `PermissionCacheService` — version tracking, stale detection |
| Permission sync | `PermissionSyncService` — auth `/permissions` fetch |
| Permission refresh | `PermissionRefreshService` — login, token refresh, app resume |
| Manage/approve enforcement | `ManagePermissionGuard`, `ApprovePermissionGuard`, `mutation_permission_validator.dart` |
| Denied access audit | `recordDeniedAccess()` on route guard failures |

## Audit & Compliance

| Feature | Implementation |
|---------|----------------|
| Event categories | `AuditEventCategory` — security, auth, workflow, system |
| Security event types | sessionRevoked, logoutAllSessions, permissionSync, permissionDenied, auditUploadFailed |
| Upload queue | `AuditUploadQueue` — offline pending/failed/retry |
| Upload service | `AuditUploadService` — batching (20), exponential backoff |
| Retention policy | `AuditRetentionPolicy` — configurable max entries |
| Correlation ID | Linked via metadata / `AuditEvent.correlationId` |
