# v5.5 — Vendor Monitoring Adapters

Release date: 2026-06-07

## Summary

Implemented swappable Sentry and Datadog monitoring adapters behind the existing `MonitoringService` abstraction. The application continues to consume only `MonitoringService`; vendor selection is environment-driven and safely falls back when credentials are missing.

## Changes

| File | Purpose |
|------|---------|
| `lib/core/monitoring/vendor_monitoring_config.dart` | Dart-define driven vendor selection and credential presence checks |
| `lib/core/monitoring/vendor_monitoring_transport.dart` | Safe transport boundary for vendor SDK/client integration |
| `lib/core/monitoring/sentry_monitoring_service.dart` | Sentry adapter for errors, events, and metrics |
| `lib/core/monitoring/datadog_monitoring_service.dart` | Datadog adapter for errors, events, and metrics |
| `lib/core/observability/observability_providers.dart` | Provider selection for debug, no-op, Sentry, and Datadog services |

## Configuration

| Dart define | Purpose |
|-------------|---------|
| `MONITORING_VENDOR=sentry\|datadog\|none` | Selects the vendor adapter |
| `SENTRY_DSN` | Enables Sentry adapter when non-empty |
| `DATADOG_CLIENT_TOKEN` | Enables Datadog adapter when non-empty |
| `DATADOG_SITE` | Datadog site, default `datadoghq.com` |
| `APP_ENV` | Tags vendor payloads with environment |
| `APP_RELEASE` | Tags vendor payloads with release |

Missing vendor credentials never crash startup. Production without configured credentials uses no-op monitoring.
