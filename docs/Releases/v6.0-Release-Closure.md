### Client alignment

- Response envelope `{ data, error }` matches Flutter `ApiEnvelopeDto`
- Auth paths match `AuthApiPaths` (`/auth/login`, `/auth/verify-otp`, etc.)
- `Environment.fromDartDefine()` supports `API_BASE_URL` override for Supabase router

### Architecture drift (documented, accepted for v6.0)

| v5.6 spec | v6.0 implementation |
|-----------|---------------------|
| JWT RS256 | HS256 + `JWT_SECRET` (staging interim) |
| Paths `/v1/auth/otp/*` | `/auth/login`, `/auth/verify-otp` (client-aligned) |
| OTP upsert user | Pre-seeded user required |
| Org-scope JWT login | School membership resolved at verify |
| Rate limiting | Not implemented |

## Sprint 3 Prerequisites

Before starting Sprint 3 (RBAC + RLS + core module APIs, v6.1):

1. **Staging stable** — v6.0 tag deployed; health + auth endpoints green  
2. **Rotate exposed secrets** — service_role key if previously shared  
3. **RLS design** — session vars (`app.tenant_id`, `app.scope`, etc.) per `TenantArchitecture.md`  
4. **Permission tables** — replace hardcoded `permissions.ts` with DB-backed RBAC  
5. **Client enum sync** — `organizationAdmin`, `JwtScope` per `ClientBackendAlignment.md`  
6. **OpenAPI consolidation** — single contract source for auth + module paths  
7. **JWT strategy decision** — RS256 migration plan or documented HS256 interim  
8. **Disable dev OTP mode** before any production-facing staging demo with real phones  

Sprint 3 scope (per `BackendRoadmap.md`): RBAC middleware, RLS on core modules, Admissions + Finance + SIS live APIs — **do not start until v6.0 closure accepted**.
