# Architecture Review — v11.1–v11.5 Evolution Foundation Hardening

**Date:** June 2026  
**Score:** 88 / 100 (school-platform hardening)

## Strengths

- Evolution module follows established repository pattern (interface → mock | API → remote → mapper)
- Widget data reuses `buildOperationsHub` — no duplicate aggregation logic
- Setup wizard provisioning delegates to existing academic/finance repositories
- Growth conversion uses `createLead` — single admissions source of truth
- Contract + integration tests cover mock ↔ API mapper parity

## Gaps

| Gap | Severity | Recommendation |
|-----|----------|----------------|
| `teacher_lesson_logs` table not migrated | Medium | Add migration when lesson logging UI ships |
| Widget cache is in-process (Edge) | Low | Move to Redis/DB cache for multi-instance deploy |
| Setup wizard provision is not idempotent | Medium | Add provision log + skip-if-exists guard |
| Growth funnel lacks date-range filters | Low | Add `from`/`to` query params |
| Parent language not wired to insight generation language param | Low | Pass saved language in generate call |
