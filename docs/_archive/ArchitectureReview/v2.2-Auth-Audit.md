## Findings

### Strengths

1. Follows Admissions/Finance repository pattern consistently
2. Feature-flagged rollout preserves mock development path
3. Audit events deduplicated between repository hooks and AuthNotifier
4. Permission sync reuses v2.0 `ServerPermissionCache` scaffold

### Risks (P1)

1. **Backend contract variance** — DTO mapper accepts multiple field aliases; formal OpenAPI contract still needed
2. **Offline permission staleness** — 12h TTL; no background sync beyond login/refresh/launch
3. **verifyOtp swallows errors** — returns null on any failure; consider typed failures in v2.3

### Residual mock paths

- Parent/teacher/student demo login unchanged
- Mock JWT builder still used in mock auth repository and refresh fallback

## Recommendations

1. Add OpenAPI contract tests against staging auth server
2. Surface API error messages in staff OTP screen
3. Wire audit POST endpoint when backend audit ingestion ships
