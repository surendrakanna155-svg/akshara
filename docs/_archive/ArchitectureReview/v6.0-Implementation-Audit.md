## Architecture Compliance

### Tenant model — PASS (Sprint 2 scope)

| Requirement | Implementation | Status |
|-------------|----------------|--------|
| Organization = tenant boundary | `sessions.tenant_id` → `organizations.id`; JWT `tenant_id` | ✅ |

| Dual memberships | `organization_memberships`, `school_memberships` | ✅ |
| School groups | Not in schema | ✅ Deferred Sprint 4 |
| `membership_permissions` | Not in schema | ✅ Deferred Sprint 3 |

### Auth architecture — PARTIAL

| Requirement | Status | Notes |
|-------------|--------|-------|
| OTP send / verify | ✅ | `/auth/login`, `/auth/verify-otp` |
| JWT 15 min TTL | ✅ | Default 900s |
| Refresh rotation | ✅ | Single-use; reuse revokes family |
| Session revocation | ✅ | Logout, logout-all, revoke |
| RS256 JWT | ❌ | HS256 + `JWT_SECRET` |
| Path `/v1/auth/otp/*` | ⚠️ | Client paths used instead |
| OTP rate limits | ❌ | Not implemented |
| Audit on login/logout | ❌ | Sprint 5 |
| Org-scope login | ❌ | School membership required at verify |
| `scope` claim variants | ⚠️ | Always `school` at issue |
| Context switch API | ❌ | Sprint 4 |

### JWT strategy — DRIFT (accepted interim)

Architecture specifies RS256 asymmetric signing. Implementation uses HS256 symmetric `JWT_SECRET`. Client `JwtDecoder` remains decode-only (no signature verification). Acceptable for staging pilot; migration required before production.
