## Executive summary

Phase 4B0 delivers the **Admissions → Finance handoff foundation** only — no fee structures, invoices, collections, or refunds. Enrollment now auto-creates a pending `admissions_fee_handoffs` row; school staff can list, send to finance, and update handoff status via three new API routes. All tenant data access uses `withTenantContext()` on the `erp_tenant` role with FORCE RLS.

**Gate status: PASS** — migration applied, function deployed, 17/17 isolation probes, 23/23 smoke tests.

## 1. Technical Report

### 1.1 Database

**Migration:** `20260612100000_admissions_fee_handoffs.sql`

| Column | Type | Notes |
|--------|------|-------|
| `id` | UUID PK | |
| `organization_id` | UUID FK | JWT `tenant_id` — not accepted from request body |
| `school_id` | UUID FK | JWT `school_id` only |
| `student_id` | UUID FK | Created at enrollment |
| `application_id` | UUID FK nullable | |
| `enrollment_id` | UUID FK nullable | |
| `academic_year` | TEXT | |
| `recommended_fee_plan_id` | TEXT nullable | Placeholder until Finance structures exist |
| `handoff_status` | TEXT | `pending` \| `sent_to_finance` \| `completed` \| `failed` |
| `student_name`, `class_label`, `admission_number` | TEXT | Display fields for queue UI |
| `needs_transport`, `needs_hostel` | BOOLEAN | From enrollment input |
| `sis_handoff_label` | TEXT | Human-readable status label |

**RLS:** Single school-scope policy (`app_current_scope() = 'school'`). No organization or parent policies — org and parent scopes cannot read raw handoff rows per TD-P0-01 / Phase 4B0 rules.

**FORCE ROW LEVEL SECURITY:** Enabled.

**Grants:** `SELECT, INSERT, UPDATE` to `erp_tenant`.

**Probe fixtures:** `b6000000-...-001` (School A), `b6000000-...-002` (School B).

### 1.2 Repository / service layer

| File | Responsibility |
|------|----------------|
| `admissions_handoffs_repository.ts` | `listFeeHandoffs`, `getFeeHandoffById`, `createHandoffFromEnrollment`, `sendHandoffToFinance`, `updateHandoffStatus` |
| `admissions_repository.ts` | `submitEnrollment` calls `createHandoffFromEnrollment` after student + enrollment insert |
| `admissions_mapper.ts` | `handoffToApi()` — camelCase client contract |

All repository functions receive `organizationId` and `schoolId` from JWT claims via handlers; no `service_role` tenant reads.

### 1.3 API routes (3 new — 26 admissions total)

| Method | Path | Handler | Permission | Scope |
|--------|------|---------|------------|-------|
| GET | `/admissions/handoffs/approved` | `handleListApprovedHandoffs` | `viewAdmissions` | School operational |
| POST | `/admissions/handoffs/send` | `handleSendToFinance` | `manageAdmissions` | School operational |
| PATCH | `/admissions/handoffs/{id}/status` | `handleUpdateHandoffStatus` | `manageAdmissions` | School operational |

**`sendToFinance` body:** `{ "handoff_id": "uuid", "fee_structure_id": "text" }` — stores `fee_structure_id` in `recommended_fee_plan_id` and sets status `sent_to_finance`.

**`updateHandoffStatus` body:** `{ "status": "completed" }` (snake_case values).

### 1.4 Auto-generation on enrollment

When `POST /admissions/enrollments` succeeds:

1. Student row created  
2. Enrollment row created  
3. `createHandoffFromEnrollment` inserts handoff with `handoff_status = pending`

### 1.5 Out of scope (confirmed not implemented)

- `finance_fee_structures`, student accounts, collections, refunds  
- `assignFeePlan` / Finance slice 2  
- Parent fee visibility  
- Org aggregate finance views  

### 1.6 Unit tests

`admissions_mapper_test.ts` — `handoffToApi` contract test (2/2 Deno tests pass).
