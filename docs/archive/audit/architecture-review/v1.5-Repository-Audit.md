## Provider Wiring Consistency

All 11 repositories registered in `repository_providers.dart`:

```dart
final xRepositoryProvider = Provider<XRepository>((ref) {
  if (ref.watch(useApiRepositoriesProvider)) {
    return ref.read(apiXRepositoryProvider);
  }
  return MockXRepository();
});
```

| Check | Status |
|-------|--------|
| `useApiRepositoriesProvider` default `false` | ✅ |
| API providers in `api_repository_providers.dart` | ✅ 11 remote DS + 11 API repos |
| Dio injection via `dioProvider` | ✅ |
| Repository tests for all mocks | ✅ `repository_test.dart` |
| API swap test | ✅ 1 test (finance + admissions) |

## Findings

### P0 — Architecture violations

| ID | Finding |
|----|---------|
| REPO-P0-01 | **None in ERP modules** — pattern correctly followed |
| REPO-P0-02 | **Mobile apps bypass repository layer** — blocks unified API migration |

### P1 — Inconsistent implementations

| ID | Finding |
|----|---------|
| REPO-P1-01 | **Sync repository interfaces** — API calls will need `Future<T>` or sync cache reads |
| REPO-P1-02 | **Integration StateProvider maps** — handoff/conversion state not in repositories |
| REPO-P1-03 | **API DTOs minimal** — only dashboard DTO per module; other endpoints not scaffolded |
| REPO-P1-04 | **Mappers throw UnimplementedError** — expected for scaffolding |
| REPO-P1-05 | **Dual provider files** — e.g. `finance_dashboard_provider.dart` + `finance_providers` pattern in newer modules |

### P2 — Cleanup opportunities

| ID | Finding |
|----|---------|
| REPO-P2-01 | Consolidate admissions/finance per-screen providers into single `*_providers.dart` |
| REPO-P2-02 | Extract shared `RepositoryProviderFlags` mixin for loading/error/empty triads |
| REPO-P2-03 | Add `RepositoryResult<T>` / `Either` for API error mapping per TechnicalArchitecture |
| REPO-P2-04 | Local datasource stubs for offline cache (Drift) — not started |
