# v2.2 Permission Sync Audit

Date: 2026-06-07  
Scope: Server permission synchronization via `GET /auth/permissions`

## Score: 8.0 / 10

## Flow

| Trigger | Action |
|---------|--------|
| App launch (`resolveSession`) | Load cache → fetch if API mode + authenticated |
| Staff login (`completeStaffLogin`) | Fetch + cache policy |
| Token refresh (`onRefreshed`) | Re-fetch permissions |
| Logout | Clear cache |

## Resolution order (`userPermissionsProvider`)

1. Authenticated session required
2. Valid non-stale `ServerPermissionCache` for matching `userId` → use `effectivePermissions`
3. Else `AuthClaims.permissions` if non-empty
4. Else role matrix fallback (`RolePermissionMatrix`)

## Cache model

- Key: `server_permission_snapshot_v1` (SharedPreferences)
- TTL: 12 hours (default)
- Policy: `ServerPermissionPolicy` with grants/revocations

## DTO mapping

Permissions accepted as:

```json
{ "data": { "permissions": [{ "permission": "viewFinance", "source": "server" }] } }
```

Or string list: `["viewFinance", "manageFinance"]`

## Findings

### Strengths

- Reuses v2.0 models without schema churn
- RBAC checks unchanged at call sites (`rbacServiceProvider`)
- Cache survives cold start before network fetch

### Gaps

1. No incremental sync / ETag — full fetch every trigger
2. Revocations depend on server sending explicit revocation list (often empty)
3. Mock mode still uses role matrix (expected)

## Test coverage

- Integration: `api staff login syncs server permissions`
- Contract: permissions DTO mapping
- Existing: `server_permission_models` contract tests

## Recommendations

1. Add `version` / `If-None-Match` support when backend supports it
2. Merge server grants with role matrix intersection for defense in depth
3. Expose sync error state in admin diagnostics (future)

## Production readiness delta

Permission sync: **3.0 → 8.0 / 10**
