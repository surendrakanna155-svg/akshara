# v6.1 Phase 3A — Tenant Access Technical Design

**Document ID:** `AKS-PHASE3A-TENANT-ACCESS-v1.0`  
**Status:** Implemented  
**Closes:** TD-P0-01 (partial)  
**Baseline:** Phase 2 auth scope expansion (`708423c`)

---

## 1. Problem

Edge Functions use Supabase `service_role`, which **bypasses RLS**. Phase 2 defined policies and `app.set_request_context` but they were not authoritative. Module APIs require a **non-bypass query path** before exposing tenant operational data.

---

## 2. Design decision

| ID | Decision | Rationale |
|----|----------|-----------|
| TA-01 | Dedicated PostgreSQL role `erp_tenant` with **NOBYPASSRLS** | Enforces RLS at database layer |
| TA-02 | Direct `postgres` driver connection for tenant queries | `service_role` Supabase client cannot enforce RLS |
| TA-03 | `withTenantContext(claims, fn)` helper | Mandatory `set_request_context` before queries |
| TA-04 | Auth plumbing unchanged on `service_role` | OTP, sessions, token issue are not tenant-data reads |
| TA-05 | `FORCE ROW LEVEL SECURITY` on core tables | Policies apply even to privileged owners in tests |
| TA-06 | Enforced isolation via `withTenantContext` probe suite | Direct `erp_tenant` login — authoritative on hosted Supabase |

---

## 3. Architecture

```
┌─────────────────────────────────────────────────────────────┐
│ Edge Function (api)                                         │
├─────────────────────────────────────────────────────────────┤
│ Auth path (unchanged)          │ Module path (Phase 3B+)    │
│ createServiceClient()          │ withTenantContext()        │
│ service_role → bypass RLS      │ erp_tenant → RLS enforced  │
│ OTP, sessions, JWT issue       │ app.set_request_context    │
└─────────────────────────────────────────────────────────────┘
```

### Connection strings

| Variable | Role | Use |
|----------|------|-----|
| `SUPABASE_SERVICE_ROLE_KEY` | `service_role` | Auth plumbing only |
| `ERP_TENANT_DATABASE_URL` | `erp_tenant` | Tenant operational queries |

Format (Supabase pooler):

```
postgresql://erp_tenant.<project-ref>:<password>@<pooler-host>:6543/postgres
```

## 5. Module API contract (Phase 3B+)

```typescript
// Required pattern for tenant data handlers:
const data = await withTenantContext(config, claims, async (db) => {
  return await db.queryObject<Row>(
    "SELECT ... FROM admissions_leads WHERE ...",
    [],
  );
});
```

**Forbidden:** `createServiceClient().from("admissions_leads")` for tenant operational data.

## 6. Isolation guarantees (enforced tests)

| Test | Scope | Expected |
|------|-------|----------|
| `school_a_cannot_see_school_b` | school | 0 rows for other school |
| `org_scope_denied_raw_school_memberships` | organization | 0 staff PII rows |
| `org_scope_denied_raw_students` | organization | 0 student PII rows |
| `org_scope_reads_aggregate_view` | organization | ≥2 `org_school_summary` rows |
| `parent_cannot_see_unlinked_student` | parent | 0 unrelated students |
| `student_sees_self_only` | student | 1 row (self) |
