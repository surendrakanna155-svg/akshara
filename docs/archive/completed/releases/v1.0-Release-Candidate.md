## Summary

Akshara ERP v1.0 Release Candidate packages the full pilot-ready ERP platform: core Admissions, Finance, and SIS write paths; complete ERP read surface; mobile parent/teacher/student APIs; pilot operations; onboarding; communication hub; payments (stub-capable); inventory-finance reconciliation; AI Copilot; smart timetable; analytics intelligence; and production launch hardening.

No new features are included beyond the validated v7.7 baseline. This RC is intended for **limited production pilot** deployment with documented integration and operational prerequisites.

## Known limitations (RC)

1. **Integration stub mode** — SMS, email, push, Razorpay, and OpenAI default to stub when production secrets absent (`Production-Integrations.md`).
2. **School B full demo seed** — Staging admin has School A membership only; School B validated via isolation probes, not full 500-student seed.
3. **Long seed runs** — Admin JWT expires ~15 min; seed script refreshes tokens between phases; use `--post-import-only` for repair runs.
4. **Broadcast latency** — Large parent audiences (~750) can take ~13 s and may transiently 502; retry succeeds.
5. **Timetable publish** — Generation validated; bulk publish of 26 section timetables may require per-section validation in ops runbook.
6. **Pen test** — Not completed in RC; scheduled for post-RC hardening (v7.8 track, not in RC scope).
7. **Flutter `pubspec` version** — Remains `0.1.0+1`; product version tracked via git tags (`v1.0-rc1`).

## Deployment checklist

1. **Pre-deploy**
   - [ ] Backup staging/production database
   - [ ] Review migrations through `20260615110000_onboarding_user_provisioning_fix.sql`
   - [ ] Set secrets per [`Production-Integrations.md`](../Operations/Production-Integrations.md)

2. **Deploy**

   - [ ] Pilot Issue Tracker = 0 open

## Rollback procedure

See [`Rollback-Checklist.md`](../Operations/Rollback-Checklist.md).

**Summary:**

1. Announce maintenance to pilot users.
2. Redeploy previous Edge Function from prior tag:
   ```bash
   git checkout v1.0-pilot-ready   # or last known-good tag
   supabase functions deploy api --no-verify-jwt
   ```
3. Do **not** run forward migrations if rollback is schema-related; use PITR or pre-deploy dump.
4. Redeploy previous Flutter web artifact.
5. Validate: `/health/ready` 200, staff login, core dashboards.
6. Document incident within 48 h.

**Do not rollback** for external provider-only outages — disable integration stub flags instead.
