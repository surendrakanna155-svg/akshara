# v2.2 Auth Server Integration

Release date: 2026-06-07

## Summary

Replaces mock staff authentication with production-ready API integration while preserving RBAC, tenant, audit, and routing behavior in mock mode.

## Scope

### Repository layer

- `AuthRepository` interface with login, verify OTP, refresh, logout, me, and permissions
- `MockAuthRepository` for development and contract parity
- `ApiAuthRepository` with DTO mapping and audit hooks

### API endpoints

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/auth/login` | Start OTP session |
| POST | `/auth/verify-otp` | Exchange OTP for JWT |
| POST | `/auth/refresh` | Rotate access token |
| POST | `/auth/logout` | Invalidate server session |
| GET | `/auth/me` | Current user profile |
| GET | `/auth/permissions` | Server RBAC grants |

### Provider wiring

- `authApiEnabledProvider` feature flag (requires `enableApiMode`)
- `authRepositoryProvider` mock/API swap
- `tokenRefreshCallbackProvider` uses repository when API enabled
- `ApiStaffOtpWorkflow` replaces mock OTP workflow in API mode

### Permission sync

- `GET /auth/permissions` cached via `ServerPermissionCache`
- Refreshed on login, token refresh, and app launch (`resolveSession`)
- `userPermissionsProvider` prefers cached server policy when valid

### Staff login UX

- ERP role picker hidden when auth API mode is active
- Server-assigned role and permissions used instead of client-side picker

### Audit events

- `login`, `logout`, `tokenRefresh` via repository audit hooks (API mode)
- Local fallback audit logging preserved for mock mode
- `accessDenied` unchanged in route guards

## Enabling API mode

```dart
// environment: enableApiMode = true
// override or configure:
authApiEnabledProvider => true
```

- Parent/teacher/student demo OTP flows (unchanged)
- Backend server implementation
- New routes or screens

## Readiness impact

Production auth client integration moves from scaffold (v2.0) to wired repository pattern. Estimated production readiness delta: **+4 points** (84 → 88) pending live backend validation.
