## The through-line (read this first)

Four structural themes explain most of the 24 P0s. They are cheaper to fix as themes than as 24 tickets.

1. **Lifecycle is missing, not the engine.** Auth, RLS, tenant isolation, the middleware chokepoint and rate limiting are genuinely well built. What does not exist is any code that can **un-do** an onboarding: no path revokes a membership, unlinks a guardian, voids a certificate, or unpublishes a result. `PRA-P0-01` and several P1s are one gap seen from different modules.
2. **Two parallel implementations, the ungoverned one wins.** Repeatedly, a correct, scoped, certified implementation exists and is shadowed by an older permissive one that actually runs: `PRA-P0-12` (route shadowing), `PRA-P0-07` (`timetable_slots` vs `academic_timetable_periods`), `PRA-P0-05` (mock adapter vs API repo), `PRA-P0-22` (inline SQL vs canonical formula). **The fix is usually deletion, not construction.**
3. **Demo scaffolding is load-bearing in production.** Mock stores and 3-person fixtures are wired into live providers with no flag guarding them: `PRA-P0-06`, `PRA-P0-08`, `PRA-P0-09`, `PRA-P0-10`. The flag system (`repository_config.dart` + `surface_backend_gate.dart`) works correctly — these paths simply **bypass it entirely**.
4. **Integration claims are asserted, not implemented.** Multiple modules return hardcoded strings claiming a Finance/SMS sync that does not exist (`PRA-P0-24`, `PRA-P1-40`), or fabricate a success/receipt (`PRA-P0-02`, `PRA-P0-16`). These are worse than absence: staff and parents act on them.

**Recurring money-integrity race** (matches the known pattern): a terminal state-write with no status guard → concurrent double-apply of a delta. Correct reference: `finance_fee_reductions_repository.ts:421`. New instances: `PRA-P0-03`, `PRA-P0-04`, `PRA-P2-10`. Notably, the previously-fixed paths all refuted cleanly — **the defect tracks the fix's blast radius, not the money's**.
