## Program laws

1. **Two separate sequential waves** — **PRC-A** (Wave A: Real School Operations Capability & Cross-Module Gap Audit) then **PRC-B** (Wave B: Product Correctness, Invariant & Edge-Case Certification). Never merged (PRC-P-05/06). Both are **implementation + certification** waves, not documentation reviews (PRC-P-07/08).
2. **Entry (auto-runnable):** when the Adaptive AI program (P3, incl. P3-AI-3 hardening exit) and its mandatory EOS gate complete, **Wave A begins automatically** if no higher-priority blocking production gate exists (PRC-X-01). Wave B begins automatically after Wave A's fixes + regression + EOS (PRC-X-04/05).
3. **Anti-disappearance law:** no row in this tracker may be deleted, merged, re-scoped or weakened during execution. A scope change requires explicit owner sign-off recorded in §7 (conflict register) — the row itself stays, marked with its disposition.
4. **EOS subordination:** the EOS remains the ONE engineering gate engine (per `CLAUDE.md` / the Constitution). PRC is an EOS-gated work program, not a competing readiness standard — every wave and fix batch closes through `/eos`.
5. **State law:** ⚪ Scheduled · 🔵 In audit/fix · ✅ Certified-with-evidence. Wave A capability rows additionally carry the mandatory classification (PRC-A-C-01..07) once audited. No row is ✅ without committed evidence.
6. **Dependency law:** a capability/metric row is never ✅ while any upstream feeding row is broken, partial, mocked or wrongly designed (PRC-A-D-01..03, PRC-A-E-30).
